# 接口错误排查指南

## 🔍 400 Bad Request 错误排查

### 现象
```json
{
  "success": false,
  "error": {
    "code": 400,
    "message": "参数验证失败" 或 "Bad Request",
    "error": "Bad Request"
  }
}
```

### 排查步骤

#### ✅ 步骤1：检查DTO定义

**问题**：DTO缺少验证装饰器

```typescript
// ❌ 错误：没有验证装饰器
export class CreateUserDto {
  email: string;
  password: string;
}

// ✅ 正确：添加完整的验证装饰器
export class CreateUserDto {
  @ApiProperty({ description: '邮箱', example: 'user@example.com' })
  @IsEmail({}, { message: '请输入有效的邮箱地址' })
  @MaxLength(100, { message: '邮箱不能超过100个字符' })
  email: string;

  @ApiProperty({ description: '密码', minLength: 8 })
  @IsString({ message: '密码必须是字符串' })
  @MinLength(8, { message: '密码至少8个字符' })
  password: string;
}
```

#### ✅ 步骤2：检查数字类型转换

**问题**：查询参数的数字没有转换

```typescript
// ❌ 错误：缺少类型转换
export class QueryDto {
  @ApiPropertyOptional({ description: '页码' })
  @IsOptional()
  @IsNumber()
  page?: number;
}

// ✅ 正确：添加类型转换
export class QueryDto {
  @ApiPropertyOptional({ description: '页码' })
  @IsOptional()
  @Type(() => Number)  // ⚠️ 必须添加！
  @IsNumber()
  page?: number;
}
```

#### ✅ 步骤3：检查布尔类型转换

**问题**：布尔值没有正确转换

```typescript
// ❌ 错误：URL参数 ?isActive=true 会被当作字符串
export class QueryDto {
  @IsOptional()
  @IsBoolean()
  isActive?: boolean;
}

// ✅ 正确：添加转换逻辑
export class QueryDto {
  @IsOptional()
  @Transform(({ value }) => value === 'true' || value === true)  // ⚠️ 必须添加！
  @IsBoolean()
  isActive?: boolean;
}
```

#### ✅ 步骤4：检查枚举值

**问题**：枚举值拼写错误或不在允许范围内

```typescript
export class QueryDto {
  @ApiPropertyOptional({ 
    description: '状态',
    enum: ['ACTIVE', 'INACTIVE', 'BANNED']  // ⚠️ 注意这些值
  })
  @IsOptional()
  @IsEnum(['ACTIVE', 'INACTIVE', 'BANNED'])
  status?: string;
}

// 前端请求时必须使用正确的枚举值
// ✅ 正确：/api/users?status=ACTIVE
// ❌ 错误：/api/users?status=active （小写）
// ❌ 错误：/api/users?status=PENDING （不存在的值）
```

#### ✅ 步骤5：检查必填字段

**问题**：必填字段没有传值

```typescript
export class CreateDto {
  // 使用 @ApiProperty（不是 @ApiPropertyOptional）表示必填
  @ApiProperty({ description: '名称' })
  @IsString()
  @MinLength(1)
  name: string;  // 必填，不能是 name?: string
}

// ❌ 错误：请求body缺少name字段
{
  "description": "test"
}

// ✅ 正确：包含所有必填字段
{
  "name": "测试",
  "description": "test"
}
```

#### ✅ 步骤6：检查ValidationPipe

**问题**：Controller方法没有使用ValidationPipe

```typescript
// ❌ 错误：缺少ValidationPipe
@Post()
async create(@Body() createDto: CreateDto) {
  return this.service.create(createDto);
}

// ✅ 正确：添加ValidationPipe
@Post()
async create(@Body(ValidationPipe) createDto: CreateDto) {
  return this.service.create(createDto);
}
```

#### ✅ 步骤7：检查DELETE请求的请求体

**问题**：DELETE 请求发送了 body，导致 JSON 解析错误

**错误现象**：
```json
{
  "message": "Unexpected token 'n', \"null\" is not valid JSON",
  "error": "Bad Request",
  "statusCode": 400
}
```

**根本原因**：
- DELETE 请求不应该有请求体（HTTP 最佳实践）
- 前端/Gateway 发送了 `data: null` 和 `Content-Type: application/json`
- 后端尝试解析字符串 `"null"` 导致 JSON 解析失败

**前端修复**：

```javascript
// ❌ 错误：DELETE 请求也发送 body
async deleteAIConfig(configId) {
  return await this.request(`/api/v1/users/ai-config/custom/${configId}`, {
    method: 'DELETE',
    data: null,  // ❌ 不应该有这个
    headers: {
      'Content-Type': 'application/json'  // ❌ 不应该有这个
    }
  })
}

// ✅ 正确：DELETE 请求不发送 body
async request(endpoint, options = {}) {
  const { method, data, params } = options;
  
  const requestConfig = {
    url: endpoint,
    method,
    params,
    headers: {
      'Authorization': this.getAuthToken() ? `Bearer ${this.getAuthToken()}` : undefined,
    }
  };
  
  // ⚠️ 只有在有 data 且不是 GET/DELETE 请求时才添加 body
  if (data && method !== 'GET' && method !== 'DELETE') {
    requestConfig.data = data;
    requestConfig.headers['Content-Type'] = 'application/json';
  }
  
  return await axios(requestConfig);
}
```

**API Gateway 修复**：

```typescript
// ❌ 错误：所有请求都转发 body
async proxyRequest(req: Request) {
  const { method, url, body } = req;
  
  const response = await this.httpService.request({
    method,
    url: targetUrl,
    headers: cleanHeaders,
    data: body,  // ❌ DELETE 请求不应该有这个
  });
}

// ✅ 正确：只在非 GET/DELETE 请求时转发 body
async proxyRequest(req: Request) {
  const { method, url, body } = req;
  
  const requestConfig: any = {
    method,
    url: targetUrl,
    headers: cleanHeaders,
  };
  
  // ⚠️ 只有在非 GET/DELETE 请求时才添加 body
  if (method !== 'GET' && method !== 'DELETE' && body !== undefined) {
    requestConfig.data = body;
  }
  
  const response = await this.httpService.request(requestConfig);
}
```

**后端 Controller 修复**：

```typescript
// ❌ 错误：缺少 @HttpCode 装饰器
@Delete(':id')
@ApiOperation({ summary: '删除资源' })
async remove(@Param('id') id: string) {
  await this.service.remove(id);
  return { message: '删除成功' };
}
// 问题：NestJS 默认 DELETE 返回 204 No Content（无响应体）

// ✅ 正确：添加 @HttpCode(HttpStatus.OK)
@Delete(':id')
@ApiOperation({ summary: '删除资源' })
@ApiParam({ name: 'id', description: '资源ID' })
@HttpCode(HttpStatus.OK)  // ⚠️ 必须添加！确保返回 200 和响应体
async remove(@Param('id') id: string) {
  await this.service.remove(id);
  return { message: '删除成功' };
}
```

**要点总结**：
1. ✅ DELETE 请求通过 URL 参数（如 `:id`）指定要删除的资源
2. ✅ DELETE 请求不应该有 `body` 和 `Content-Type`
3. ✅ 所有 DELETE 接口都要添加 `@HttpCode(HttpStatus.OK)` 才能返回消息体
4. ✅ API Gateway 和 HTTP 客户端要过滤 GET/DELETE 请求的 body

**影响范围**：
- 前端 API Manager
- API Gateway 所有代理服务（users/auth/admin/novel/payment）
- 所有 DELETE 接口

## 🔍 401 Unauthorized 错误排查

### 现象
```json
{
  "success": false,
  "error": {
    "code": 401,
    "message": "访问令牌缺失" 或 "Invalid token" 或 "Unauthorized",
    "error": "Unauthorized"
  }
}
```

### 排查步骤

#### ✅ 步骤1：检查Guards配置

**问题**：忘记添加JwtAuthGuard

```typescript
// ❌ 错误：没有认证守卫

  @Get('profile')
  getProfile() {}
}

// ✅ 正确：添加认证守卫
@Controller()
@UseGuards(JwtAuthGuard)  // ⚠️ 控制器级别
@ApiBearerAuth('JWT-auth')  // ⚠️ Swagger文档
export class UserController {
  @Get('profile')
  getProfile(@Request() req) {
    console.log('User:', req.user);  // 可以获取用户信息
  }
}
```

#### ✅ 步骤2：检查JWT策略配置

**问题**：JwtStrategy没有配置或配置错误

```typescript
// strategies/jwt.strategy.ts
import { Injectable, UnauthorizedException } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { PassportStrategy } from '@nestjs/passport';
import { ExtractJwt, Strategy } from 'passport-jwt';

@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor(private configService: ConfigService) {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration: false,
      secretOrKey: configService.get<string>('JWT_SECRET'),  // ⚠️ 必须配置
    });
  }

  async validate(payload: any) {
    if (!payload) {
      throw new UnauthorizedException('Invalid token payload');
    }
    
    return {
      id: payload.sub || payload.id,
      email: payload.email,
      role: payload.role,
    };
  }
}
```

**检查Module配置**：

```typescript
// app.module.ts 或 xxx.module.ts
@Module({
  imports: [
    PassportModule.register({ defaultStrategy: 'jwt' }),
    JwtModule.registerAsync({
      imports: [ConfigModule],
      useFactory: async (configService: ConfigService) => ({
        secret: configService.get<string>('JWT_SECRET'),
        signOptions: { expiresIn: '7d' },
      }),
      inject: [ConfigService],
    }),
  ],
  providers: [JwtStrategy],  // ⚠️ 必须提供JwtStrategy
  exports: [JwtStrategy, PassportModule],
})
export class AuthModule {}
```

## 🔍 403 Forbidden 错误排查（管理员接口）

### 现象
```json
{
  "success": false,
  "error": {
    "code": 403,
    "message": "权限不足，需要管理员权限" 或 "需要以下角色之一: ADMIN",
    "error": "Forbidden"
  }
}
```

### 排查步骤

#### ✅ 步骤1：检查@Roles装饰器

**问题**：忘记添加@Roles装饰器

```typescript
// ❌ 错误：没有@Roles装饰器
@Get('users')
@UseGuards(AdminAuthGuard, RoleGuard)
async getUsers() {}

// ✅ 正确：添加@Roles装饰器
@Get('users')
@Roles('ADMIN')  // ⚠️ 必须添加！
@UseGuards(AdminAuthGuard, RoleGuard)
async getUsers() {}
```

#### ✅ 步骤2：检查AdminAuthGuard配置

**问题**：AdminAuthGuard没有正确验证角色

```typescript
// guards/admin-auth.guard.ts
@Injectable()
export class AdminAuthGuard implements CanActivate {
  async canActivate(context: ExecutionContext): Promise<boolean> {
    const request = context.switchToHttp().getRequest<Request>();
    const token = this.extractTokenFromHeader(request);

    if (!token) {
      throw new UnauthorizedException('访问令牌缺失');
    }

    try {
      const payload = await this.jwtService.verifyAsync(token, { 
        secret: this.configService.get<string>('JWT_SECRET') 
      });
      
      // ⚠️ 验证用户角色
      if (payload.role !== 'ADMIN') {
        throw new UnauthorizedException('权限不足，需要管理员权限');
      }

      request['user'] = payload;
      return true;
    } catch (error) {
      throw new UnauthorizedException('无效的访问令牌');
    }
  }
}
```

#### ✅ 步骤3：检查RoleGuard配置

```typescript
// guards/role.guard.ts
@Injectable()
export class RoleGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredRoles = this.reflector.get<string[]>('roles', context.getHandler());
    
    console.log('Required Roles:', requiredRoles);  // 调试
    
    if (!requiredRoles) {
      return true;
    }

    const request = context.switchToHttp().getRequest();
    const user = request.user;

    console.log('User:', user);  // 调试
    console.log('User Role:', user?.role);  // 调试

    if (!user) {
      throw new ForbiddenException('用户信息缺失');
    }

    const hasRole = requiredRoles.includes(user.role);
    
    if (!hasRole) {
      throw new ForbiddenException(`需要以下角色之一: ${requiredRoles.join(', ')}`);
    }

    return true;
  }
}
```


#### ✅ 步骤5：检查Guards顺序

**问题**：Guards顺序错误

```typescript

// ✅ 正确：AdminAuthGuard在前（先认证，再授权）
@UseGuards(AdminAuthGuard, RoleGuard)
export class AdminController {}
```

## 📋 快速排查检查清单

当接口出错时，按顺序检查：

### 404错误检查清单
- [ ] Controller路径是否正确（微服务不要加前缀）
- [ ] 服务是否正常启动
- [ ] API Gateway是否正确代理
- [ ] 端口配置是否正确
- [ ] 路径拼写是否正确
- [ ] Controller是否在Module中注册
- [ ] Module是否导入到AppModule

### 401错误检查清单
- [ ] 是否添加了@UseGuards(JwtAuthGuard)
- [ ] 是否添加了@ApiBearerAuth('JWT-auth')
- [ ] JwtStrategy是否正确配置
- [ ] JWT_SECRET是否配置且一致
- [ ] 前端是否发送Authorization头
- [ ] Token格式是否正确（Bearer <token>）
- [ ] Token是否过期
- [ ] API Gateway是否转发Authorization头

### 400错误检查清单
- [ ] DTO是否添加了所有验证装饰器
- [ ] 数字类型是否添加了@Type(() => Number)
- [ ] 布尔类型是否添加了@Transform
- [ ] 枚举值是否正确
- [ ] 是否使用了@Body(ValidationPipe)
- [ ] 必填字段是否都提供了值
- [ ] 字段类型是否匹配
- [ ] **DELETE请求是否发送了body（应该不发送）**
- [ ] **前端 GET/DELETE 请求是否过滤了 body 和 Content-Type**
- [ ] **API Gateway 是否过滤了 GET/DELETE 请求的 body**
- [ ] **DELETE 接口是否添加了 @HttpCode(HttpStatus.OK)**

### 403错误检查清单
- [ ] 是否添加了@Roles装饰器
- [ ] AdminAuthGuard是否正确验证角色
- [ ] RoleGuard是否正确配置
- [ ] JWT Token中role字段是否为ADMIN
- [ ] Guards顺序是否正确

---

**记住**：大多数错误都是由于配置不完整或不一致导致的。仔细对照检查清单，逐项排查！
