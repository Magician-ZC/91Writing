## 概述

本文档用于指导新接口的开发，确保所有接口遵循统一的规范，避免常见的400、401、404等错误。

### 为什么会出现400/401/404错误？

| 错误代码 | 原因 | 解决方案 |
|---------|------|---------|
| **400 Bad Request** | DTO验证失败、参数格式错误 | 严格按照DTO规范定义字段验证 |
| **401 Unauthorized** | 缺少认证信息、JWT token无效 | 正确配置Guards和装饰器 |
| **404 Not Found** | 路由配置错误、Controller路径错误 | 检查API Gateway代理和Controller路径 |

## 架构说明

### 系统架构
```
前端 → API Gateway (端口:3000) → 微服务
                ↓
        ┌──────────────────┐
        │   admin-service  │ (管理员服务)
        │   user-service   │ (用户服务)
        │   auth-service   │ (认证服务)
        │   novel-service  │ (小说服务)
        │   ai-service     │ (AI服务)
        │   payment-service│ (支付服务)
        └──────────────────┘
```

### 路由规则

**API Gateway路由前缀**：
- `/admin/*` → admin-service
- `/users/*` → user-service  
- `/auth/*` → auth-service
- `/novels/*` → novel-service
- `/ai/*` → ai-service
- `/payment/*` → payment-service

**重要规则**：
1. API Gateway的Controller使用 `@Controller('admin')` 等前缀
2. 微服务的Controller使用 `@Controller()` **不带前缀**（因为Gateway已经处理了路由）
3. 微服务内部的子路由直接写路径即可，如 `@Get('dashboard/stats')`

## 常见错误解决方案

### ❌ 错误1：Controller双重前缀导致404

**错误示例**：
```typescript
// ❌ 错误：在微服务中使用了前缀
@Controller('admin')  // 错误！
export class AdminController {
  @Get('users')  // 实际路径变成 /admin/admin/users
  getUsers() {}
}
```

**正确示例**：
```typescript
// ✅ 正确：微服务不使用前缀
@Controller()  // 正确！
export class AdminController {
  @Get('users')  // 实际路径是 /admin/users
  getUsers() {}
}
```

### ❌ 错误2：缺少认证Guard导致401

**错误示例**：
```typescript
// ❌ 错误：忘记添加认证Guard
@Controller()
export class UserController {
  @Get('profile')  // 任何人都能访问，不安全！
  getProfile() {}
}
```

**正确示例**：
```typescript
// ✅ 正确：添加认证Guard
@Controller()
@UseGuards(JwtAuthGuard)  // 控制器级别的Guard
@ApiBearerAuth('JWT-auth')  // Swagger文档
export class UserController {
  @Get('profile')
  getProfile(@Request() req) {
    // req.user 包含用户信息
  }
}
```

### ❌ 错误3：DTO验证不完整导致400

**错误示例**：
```typescript
// ❌ 错误：没有使用验证装饰器
export class CreateUserDto {
  email: string;  // 缺少验证
  password: string;  // 缺少验证
}
```

**正确示例**：
```typescript
// ✅ 正确：完整的DTO验证
export class CreateUserDto {
  @ApiProperty({ description: '邮箱', example: 'user@example.com' })
  @IsEmail({}, { message: '请输入有效的邮箱地址' })
  @MaxLength(100, { message: '邮箱不能超过100个字符' })
  email: string;

  @ApiProperty({ description: '密码', minLength: 8 })
  @IsString({ message: '密码必须是字符串' })
  @MinLength(8, { message: '密码至少8个字符' })
  @MaxLength(50, { message: '密码不能超过50个字符' })
  @Matches(/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)/, {
    message: '密码必须包含大小写字母和数字'
  })
  password: string;
}
```

### 3. 管理员认证Guard

确保你的管理员服务中有以下Guard：

**guards/admin-auth.guard.ts**:
```typescript
import {
  Injectable,
  CanActivate,
  ExecutionContext,
  UnauthorizedException,
} from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { JwtService } from '@nestjs/jwt';
import { Request } from 'express';

@Injectable()
export class AdminAuthGuard implements CanActivate {
  constructor(
    private readonly jwtService: JwtService,
    private readonly configService: ConfigService,
  ) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const request = context.switchToHttp().getRequest<Request>();
    const token = this.extractTokenFromHeader(request);

    if (!token) {
      throw new UnauthorizedException('访问令牌缺失');
    }

    try {
      const secret = this.configService.get<string>('JWT_SECRET');
      const payload = await this.jwtService.verifyAsync(token, { secret });
      
      // ⚠️ 验证用户角色是否为管理员
      if (payload.role !== 'ADMIN') {
        throw new UnauthorizedException('权限不足，需要管理员权限');
      }

      request['user'] = payload;
      return true;
    } catch (error) {
      if (error instanceof UnauthorizedException) {
        throw error;
      }
      throw new UnauthorizedException('无效的访问令牌');
    }
  }

  private extractTokenFromHeader(request: Request): string | undefined {
    const [type, token] = request.headers.authorization?.split(' ') ?? [];
    return type === 'Bearer' ? token : undefined;
  }
}
```

**guards/role.guard.ts**:
```typescript
import {
  Injectable,
  CanActivate,
  ExecutionContext,
  ForbiddenException,
} from '@nestjs/common';
import { Reflector } from '@nestjs/core';

@Injectable()
export class RoleGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredRoles = this.reflector.get<string[]>('roles', context.getHandler());
    
    if (!requiredRoles) {
      return true;
    }

    const request = context.switchToHttp().getRequest();
    const user = request.user;

    if (!user) {
      throw new ForbiddenException('用户信息缺失');
    }

    const hasRole = requiredRoles.includes(user.role);
    
    if (!hasRole) {
      throw new ForbiddenException(`需要以下角色之一: ${requiredRoles.join(', ')}`);
    }

    return true;
  }
}
```

```typescript
import { Injectable, UnauthorizedException } from '@nestjs/common';
import { AuthGuard } from '@nestjs/passport';

@Injectable()
export class JwtAuthGuard extends AuthGuard('jwt') {
  handleRequest(err: any, user: any, info: any) {
    if (err || !user) {
      throw err || new UnauthorizedException('Invalid token');
    }
    return user;
  }
}
```

### 2. JWT策略配置

每个需要认证的服务都需要配置JWT策略：

**strategies/jwt.strategy.ts**:
```typescript
import { Injectable, UnauthorizedException } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { PassportStrategy } from '@nestjs/passport';
import { ExtractJwt, Strategy } from 'passport-jwt';

@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor(private configService: ConfigService) {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration: false,
      secretOrKey: configService.get<string>('JWT_SECRET'),
    });
  }

  async validate(payload: any) {
    if (!payload) {
      throw new UnauthorizedException('Invalid token payload');
    }
    
    return {
      id: payload.sub || payload.id,
      email: payload.email,
      role: payload.role,
      tenantId: payload.tenantId,
    };
  }
}
```

### 3. Module配置

```typescript
import { Module } from '@nestjs/common';
import { JwtModule } from '@nestjs/jwt';
import { PassportModule } from '@nestjs/passport';
import { ConfigModule, ConfigService } from '@nestjs/config';
import { JwtStrategy } from './strategies/jwt.strategy';

@Module({
  imports: [
    PassportModule.register({ defaultStrategy: 'jwt' }),
    JwtModule.registerAsync({
      imports: [ConfigModule],
      useFactory: async (configService: ConfigService) => ({
        secret: configService.get<string>('JWT_SECRET'),
        signOptions: {
          expiresIn: '7d',
        },
      }),
      inject: [ConfigService],
    }),
  ],
  providers: [JwtStrategy],
  exports: [JwtStrategy, PassportModule, JwtModule],
})
export class AuthModule {}
```

## 响应格式规范

### 1. 响应拦截器

每个服务都应该有统一的响应拦截器：

**interceptors/response.interceptor.ts**:
```typescript
import {
  Injectable,
  NestInterceptor,
  ExecutionContext,
  CallHandler,
} from '@nestjs/common';
import { Observable } from 'rxjs';
import { map } from 'rxjs/operators';

export interface Response<T> {
  success: boolean;
  data: T;
  message?: string;
  timestamp: string;
}

@Injectable()
export class ResponseInterceptor<T> implements NestInterceptor<T, Response<T>> {
  intercept(context: ExecutionContext, next: CallHandler): Observable<Response<T>> {
    return next.handle().pipe(
      map((data) => {
        // 如果返回的数据已经是标准格式，直接返回
        if (data && typeof data === 'object' && 'success' in data) {
          return data;
        }

        // 包装为标准响应格式
        return {
          success: true,
          data,
          message: this.getSuccessMessage(context),
          timestamp: new Date().toISOString(),
        };
      }),
    );
  }

  private getSuccessMessage(context: ExecutionContext): string {
    const request = context.switchToHttp().getRequest();
    const method = request.method;

    if (method === 'POST') return '创建成功';
    if (method === 'PUT' || method === 'PATCH') return '更新成功';
    if (method === 'DELETE') return '删除成功';
    return '';
  }
}
```

## 错误处理规范

### 1. 全局异常过滤器

**filters/all-exceptions.filter.ts**:
```typescript
import {
  ExceptionFilter,
  Catch,
  ArgumentsHost,
  HttpException,
  HttpStatus,
  Logger,
} from '@nestjs/common';
import { Request, Response } from 'express';

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  private readonly logger = new Logger(AllExceptionsFilter.name);

  catch(exception: unknown, host: ArgumentsHost): void {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    let status: number;
    let message: string;
    let error: string;

    if (exception instanceof HttpException) {
      status = exception.getStatus();
      const exceptionResponse = exception.getResponse();
      
      if (typeof exceptionResponse === 'object' && exceptionResponse !== null) {
        message = (exceptionResponse as any).message || exception.message;
        error = (exceptionResponse as any).error || 'Http Exception';
      } else {
        message = exceptionResponse as string;
        error = 'Http Exception';
      }
    } else {
      status = HttpStatus.INTERNAL_SERVER_ERROR;
      message = '服务器内部错误';
      error = 'Internal Server Error';
    }

    // 记录错误日志
    const errorInfo = {
      timestamp: new Date().toISOString(),
      path: request.url,
      method: request.method,
      statusCode: status,
      error,
      message,
    };

    if (status >= 500) {
      this.logger.error('服务器错误', exception);
    } else if (status >= 400) {
      this.logger.warn('客户端错误', errorInfo);
    }

    // 返回错误响应
    response.status(status).json({
      success: false,
      error: {
        code: status,
        message,
        error,
        timestamp: errorInfo.timestamp,
        path: errorInfo.path,
      },
    });
  }
}
```

```typescript
import {
```

```typescript
  ApiParam,
  ApiQuery,

import { JwtAuthGuard } from '@app/common/guards';
import { NovelService } from './novel.service';
import { CreateNovelDto, UpdateNovelDto, QueryNovelDto } from './dto';

@ApiTags('novels')
@ApiBearerAuth('JWT-auth')
@Controller('novels')  // API Gateway会处理/novels前缀

  constructor(private readonly novelService: NovelService) {}

  @Post()

  @Get()

  async findAll(
    @Request() req,
    @Query() queryDto: QueryNovelDto,
  ) {
    return this.novelService.findAll(req.user.id, queryDto);
  }

  @Get(':id')
  @ApiOperation({ summary: '获取小说详情' })
  @ApiParam({ name: 'id', description: '小说ID' })
  @ApiResponse({ status: 200, description: '获取成功' })
  @ApiResponse({ status: 404, description: '小说不存在' })
  async findOne(
    @Param('id') id: string,
    @Request() req,
  ) {
    return this.novelService.findOne(id, req.user.id);
  }

  @Patch(':id')
  @ApiOperation({ summary: '更新小说' })
  @ApiParam({ name: 'id', description: '小说ID' })
  @ApiResponse({ status: 200, description: '更新成功' })
  async update(
    @Param('id') id: string,
    @Request() req,
    @Body(ValidationPipe) updateDto: UpdateNovelDto,
  ) {
    return this.novelService.update(id, req.user.id, updateDto);
  }

  @Delete(':id')
  @ApiOperation({ summary: '删除小说' })
  @ApiParam({ name: 'id', description: '小说ID' })
  @ApiResponse({ status: 200, description: '删除成功' })

    @Param('id') id: string,
    @Request() req,
  ) {
    await this.novelService.remove(id, req.user.id);
    return { message: '删除成功' };
  }
}
```

```typescript
import {
```

## 常见问题FAQ

### Q1: 为什么我的接口返回404？

**A**: 检查以下几点：
1. API Gateway的路由配置是否正确
2. 微服务的Controller是否使用了错误的前缀
3. 微服务是否正常启动
4. API Gateway能否访问微服务（检查端口和地址）

### Q2: 为什么我的接口返回401？

**A**: 检查以下几点：
1. 是否添加了`@UseGuards(JwtAuthGuard)`
2. 前端是否发送了Authorization头
3. JWT token是否有效（未过期）
4. JwtStrategy是否正确配置
5. JWT_SECRET是否一致

### Q3: 为什么我的接口返回400？

**A**: 检查以下几点：
1. DTO是否添加了所有必要的验证装饰器
2. 数字类型是否添加了`@Type(() => Number)`
3. 枚举值是否正确
4. 必填字段是否都提供了值
5. 字符串长度是否超过限制

### Q4: 管理员接口返回403权限不足？

**A**: 检查以下几点：
1. 是否添加了`@Roles('ADMIN')`装饰器
2. AdminAuthGuard是否正确验证角色
3. 用户的role字段是否为'ADMIN'
4. RoleGuard是否正确配置

### Q5: 如何调试接口问题？

**A**: 建议步骤：
1. 查看服务日志输出
2. 使用Postman测试接口
3. 检查网络请求的Headers和Body
4. 在Controller方法中添加console.log
5. 使用调试器断点调试
